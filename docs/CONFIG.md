# 配置参考

配置文件为项目根目录的 `config.yaml`，首次启动时由 `default_config()` 自动生成，在网页上保存时原子写回（先写 `.tmp` 再 `replace`）。

完整示例见 [examples/config.example.yaml](../examples/config.example.yaml)。

> `config.yaml` 含连接地址与口令，已在 `.gitignore` 中排除，请不要提交。

## 1. 顶层结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `connections` | list | 多套 IoTDB 连接 |
| `active_connection` | string | 当前使用的连接 `id`；缺失时回落到第一套 |
| `prefix` | object | 路径前缀与拼接规则 |
| `groups` | map | `BMS` / `PCS` / `XB` 三组层级定义 |
| `pcs_sub` | bool | 是否启用 PCS 子设备层，默认 `false` |
| `xb_subs` | list | 启用的箱变子设备层 `key` 列表，如 `[byr, lvr]`；默认 `[]`（只写箱变本体）。层定义来自 `groups.XB`，界面上可增删改。旧字段 `xb_sub: true` 等价于「启用配置里定义的全部子层」 |
| `rules` | list | 测点 → 值域 / 单位 / 变化模型 |
| `write` | object | 写入参数 |

前端提交的 JSON 允许用驼峰 `activeConnection` / `pcsSub` / `xbSubs`，后端会归一为下划线形式。

## 2. connections

```yaml
connections:
  - id: cfg1          # 唯一标识，前端用它做切换
    name: 本地         # 展示名
    host: 127.0.0.1
    port: 6667
    user: root
    password: root
    database: root.cm # 写入前会确保该库存在
```

| 字段 | 默认值 | 说明 |
|---|---|---|
| `id` | — | 必填，重复会导致切换异常 |
| `name` | — | 必填，显示在顶栏与连接列表 |
| `host` | `127.0.0.1` | 主机名或 IP |
| `port` | `6667` | IoTDB RPC 端口 |
| `user` / `password` | `root` / `root` | 认证信息 |
| `database` | `root.cm` | 目标库，写入前自动创建 |

## 3. prefix

```yaml
prefix:
  station: cm
  zone: z01
  signal: yc
  order: reverse
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `station` | 字符串 | 场站编码，路径第二段 |
| `zone` | 字符串 | 站区号，路径第三段 |
| `signal` | `yc` \| `yx` | `yc` 遥测 → 全部 `FLOAT`；`yx` 遥信 → 全部 `BOOLEAN` |
| `order` | `forward` \| `reverse` | `forward` = `d.c`；`reverse` = `c.d`。**只影响堆与舱两层的顺序** |

拼接结果：`root.{station}.{zone}.{signal}`，例如 `root.cm.z01.yc`。

## 4. groups 与层级

`groups` 下的键固定为 `BMS` / `PCS` / `XB`，每个值是层级数组：

```yaml
groups:
  BMS:
    - key: cu
      name: 簇
      range: c001-c074
      measures: [totv, toti, totp, soc, rsv01-rsv06]
```

| 字段 | 说明 |
|---|---|
| `key` | 层级键：BMS 用 `d/c/cu/p/m`，PCS 用 `pcs/pcsd`，箱变用 `xb` + 任意多个自定义子层（示例 `byr/lvr`）。前三类固定，箱变子层可在界面上增删改；`engine.py` 按这些键取值 |
| `name` | 展示名（堆 / 舱 / 簇 / 包 / 模组） |
| `range` | 该层编码范围，决定这一层有多少节点；空或非法 → 该层 0 个节点 |
| `measures` | 挂在该层的测点，支持单点与区间；**空数组表示该层不写入** |

层级深度固定为五层，节点数相乘：

```
root.cm.z01.yc.d0001.c101.c001.p01.m01
              └ d ┘ └ c ┘ └cu┘ └p┘ └m┘
```

PCS 与箱变是独立分支，不参与上面的相乘：

```
root.cm.z01.yc.pcs0101          # PCS
root.cm.z01.yc.pcs0101.d01      # PCS 子设备（pcs_sub: true）
root.cm.z01.yc.35packtran101    # 箱变
root.cm.z01.yc.35packtran101.byr01  # 箱变 · 变压器室（xb_subs: [byr]）
root.cm.z01.yc.35packtran101.lvr01  # 箱变 · 低压室（xb_subs: [byr, lvr]）
```

箱变子设备层不限于一层：`groups.XB` 里 `xb` 之后的每一层都是一个可选子设备层，
默认示例 `byr`（变压器室）、`lvr`（低压室）。层 key、名称、范围都可以在界面
「路径与结构 → 箱变 → ＋ 添加子层」里直接改，也可以删掉重新加。各子层是**兄弟节点**，
都直接挂在箱变下，节点数各自为 `xb × 该层范围`，互不相乘；范围写 `d01-d04` 时，
每台箱变下会展开 4 台子设备。

PCS 与箱变的开关互相独立：`pcs_sub` 管 `pcsd`，`xb_subs` 管箱变的所有子层；
未启用的层 `counts` 为 0、生成器不进入该层，序列数与设备数与开启前完全一致。

## 5. 编码范围语法

`range` 支持三种写法，可混用，用逗号（中英文均可）或空格分隔：

| 类型 | 示例 | 展开结果 |
|---|---|---|
| 数值连续 | `d0001-d0020` | d0001 … d0020（按起始宽度补零） |
| 尾缀连续 | `c101a-c101d` | c101a、c101b、c101c、c101d |
| 逐项列举 | `c101,c201` | c101、c201 |
| 混合 | `pcs0101-pcs0103,pcs0201` | pcs0101…0103 + pcs0201 |

约束：

- 数值区间要求**前后缀相同**：`c001-c074` 合法，`c001-d074` 非法；
- 位数按起始值宽度补零：`c001-c074` 得 `c001…c074`；`c1-c3` 得 `c1…c3`；
- 字母区间只支持**末尾单字母**递增，且不跨大小写；
- 每个展开后的编码必须"**含数字且只含字母数字**"（`ZZZ` 非法，`c1a` 非法）；
- 空字符串视为"未填"，不报错，但该层 0 节点，规模估算会提示。

前后端对同一份输入必须给出相同结果，改动规则时同步三处：`server/parser.py`、`index.html` 的 `parseRange`、`tests/test_parser.py`。

## 6. 测点定义

| 类型 | 示例 | 说明 |
|---|---|---|
| 单点 | `soc` | 必须以字母开头，后续可含数字与下划线 |
| 区间 | `v001-v099` | 前缀相同、位数一致，按数值递增展开 |
| 区间 | `rsv01-rsv07` | 同上，得到 7 个测点 |
| 非法 | `v001-t012` | 前后缀不一致，无法解析，会被忽略 |

补零宽度**按起始值的位数**决定：`v001-v026` 展开为 `v001…v026`，而 `v1-v099` 会展开成 `v1…v99`——后者能解析但通常不是你想要的，写区间时保持两端位数一致。

测点数量 = 该层每台设备的列数。`tests/test_parser.py` 覆盖了这些边界。

## 7. rules

```yaml
rules:
  - cat: 电压
    min: 3.0
    max: 4.2
    unit: V
    model: walk
    match: "v*, *vol"
    period: 86400
```

| 字段 | 说明 |
|---|---|
| `cat` | 规则分类，仅用于展示 |
| `min` / `max` | 值域；`max < min` 时自动交换 |
| `unit` | 单位，仅用于界面展示 |
| `model` | 变化模型，见下表 |
| `match` | 匹配式，逗号分隔，支持精确名、区间、通配 |
| `period` | 正弦周期（秒），仅 `sine` 使用 |

### 变化模型

| 模型 | 行为 | 典型用途 |
|---|---|---|
| `walk` | 在上次值上随机游走，步长 = 量程 2%，越界半幅回弹 | 电压、SOC |
| `sine` | `mid + sin(2πt/period + 随机相位) × 量程/2` | 温度、功率 |
| `mono` | 单调累加，到上限回绕到下限 | 累计电量 |
| `state` | 在 `{min, mid, max}` 三档间随机 | 工作模式 |
| `const` | 恒为下限 | 预留位（0） |
| `flip` | 在上下限之间翻转 | 遥信 0/1 |

每条序列（`设备路径.测点`）独立维护状态，惰性创建；随机种子固定，同一配置可复现。

### 匹配优先级

匹配式会被预编译并**按特异性排序**，否则 `t*` 会抢走 `totp`、`*de` 会抢走 `workmode`：

| 优先级 | 形式 | 权重 | 说明 |
|---|---|---|---|
| 1 | 精确名 / 区间展开 | 100 | `soc`、`rsv01-rsv07` |
| 2 | 单字母 + `*` | 40 | `v*`、`t*`，只匹配"字母 + 数字"型名字 |
| 3 | 前后缀 glob | `10 + 前缀长 + 后缀长` | `*vol`、`*tem`、`*ce` |

未匹配到任何规则的测点按 `const`、值域 `[0, 1]` 处理。

## 8. write

| 字段 | 默认 | 说明 |
|---|---|---|
| `interval_ms` | `1000` | 相邻点时间间隔。只决定数据密度，程序不会真的按此等待（持续写入除外） |
| `mode` | `realtime` | `realtime` 末点对齐当前时间向前倒推；`history` 从 `history_start` 往后铺 |
| `batch` | `1000` | 每批提交的设备数。调大更快更占内存，调小停止更灵敏，不影响总点数 |
| `points_per_device` | `10` | 每设备写入的时间点数；**留空 / `null` / `0` = 持续写入**，直到手动停止 |
| `history_start` | `''` | `history` 模式起始时刻，格式 `YYYY-MM-DD HH:MM:SS`；留空则回退为当前时间 |
| `rate_limit` | `0` | 每秒最多写入点数，`0` 不限速；按"已写点数 / 目标速率"计算应到时刻，超前才等待 |
| `threads` | `4` | 预留字段，当前写入为串行提交 |
| `dry_run` | `false` | `true` 时不连真库，用 `MockSession` 走完整流程 |
| `targets` | `[BMS, PCS, XB]` | 写入对象：只生成并写入这些设备大类。取值在 `BMS` / `PCS` / `XB` 内，大小写不敏感，顺序与重复会被规范化 |

## 9. 常见问题

**改了范围但设备数没变**
前端只在 `input` 事件里更新状态，若通过脚本改 `value` 而未派发事件，规模不会刷新；正常手输不受影响。另外某层 `measures` 为空时，该层设备不计入"待写设备"。

**进度停在 100% 之前**
分母用的是 `writable_devices`（只统计挂了测点的设备）。如果所有层都配了测点仍不收敛，检查是否点过"停止"——中断时进度按实际完成量停在半程，属预期行为。

**路径顺序反了**
`order` 只控制堆与舱：`reverse` 得 `c101.d0001`，`forward` 得 `d0001.c101`。其余层级顺序固定。

**改 `yc` 为 `yx` 后写入报类型冲突**
序列类型由首次写入决定，auto-schema 不会改已存在的类型。需要先删除对应序列（或换目标库）再写。

**`points_per_device` 填 0 变成持续写入**
这是刻意设计：`0`、空字符串、`null` 都归一为"不限总量"。想写 1 个点请填 `1`。

**只想补一部分数据（比如只写箱变）**
把 `write.targets` 写成 `[XB]`，界面「生成与预览 → 写入对象」里也可以直接勾选。被排除的分组既不展开、也不进 Tablet，进度分母（`target_devices`）与总点数同步收窄；`scale()` 里的 `series` / `writable_devices` 仍是整站口径，方便对照。

**写入对象全选不上会怎样**
`targets: []` 在解析时按"全部"兜底，避免配置写错变成静默不写；若所选分组确实没有可写设备（没配测点、范围为空），`run()` 直接报错并说明是哪个分组，不会连库。

**箱变也要挂子设备**
界面「路径与结构 → 箱变」里点「＋ 添加子层」，填层 key（如 `hvr`）、名称（高压室）与设备范围
（`hvr01-hvr03` 表示每台箱变 3 台高压室子设备），保存后自动启用；也可以在 `groups.XB` 里手工加一条，
再把 key 写进 `xb_subs`。默认示例只给 `byr`（变压器室，`byr01`）与 `lvr`（低压室，`lvr01`）两层，
删掉后不会被自动补回来。开启后额外产出 `35packtran101.hvr01.hvvol` 这类设备，
节点数各自 = 箱变数 × 该层设备数；未列进 `xb_subs` 的层不产出设备。
