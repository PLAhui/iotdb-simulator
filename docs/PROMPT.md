## 一、主提示词（可直接复制）

你是一名擅长「工程工具型单页应用」的全栈工程师。请从零实现一个 **IoTDB 数据模拟器**：本地启动一个网页，用可视化方式配置储能电站的设备层级与测点，然后按可配置的规则批量生成数据，写入 Apache IoTDB。

### 0. 一句话定位

> 不是"点一下生成几万行 CSV"的脚本，而是**面向整站 68 万时间序列的可视化模拟工作台**——路径可拼、测点可配、规则可调、写入可停、结果可看。

### 1. 技术栈与硬约束

- 后端：Python 3.10+ / FastAPI / uvicorn，客户端 `apache-iotdb>=1.3,<2`，配置用 `PyYAML` 持久化到 `config.yaml`。
- 前端：**单个 `index.html`**，原生 HTML/CSS/JS，不引入构建工具、不引入前端框架，**不依赖外网 CDN**（内网环境）。
- 启动：`start.sh` → `python3 -m uvicorn server.app:app --host 127.0.0.1 --port 8000`，默认端口 8000（开发时可换 8791）。只监听 127.0.0.1。
- 目录：`server/{app,config,parser,engine,rules,writer}.py` + `index.html` + `config.yaml` + `start.sh` + `requirements.txt`。
- 所有代码注释、界面文案用中文；注释解释**为什么**这么做（踩过的坑要写清），不要写"这是一个函数"这类废话。

### 2. 数据模型（前后端共用一套语义）

`config.yaml` 的结构即为前后端唯一契约：

```yaml
connections:            # 多套连接，可切换
  - {id, name, host, port, user, password, database}
active_connection: cfg1
prefix: {station: cm, zone: z01, signal: yc, order: reverse}
groups:                 # BMS / PCS / XB 三组
  BMS:
    - key: d            # 层级键：d=堆 c=舱 cu=簇 p=包 m=模组
      name: 堆
      range: d0001-d0002      # 该层编码范围 → 决定这一层有多少节点
      measures: [soh, rsv01-rsv07]   # 该层挂的测点，支持单点与区间
  PCS: [{key: pcs, ...}, {key: pcsd, ...}]
  XB:  [{key: xb, ...}, {key: byr, ...}, {key: lvr, ...}]   # 第一层是本体，之后每层都是一个子设备层（可增删改）
pcs_sub: false          # PCS 是否启用子设备层（只有 pcsd 一层）
xb_subs: []             # 启用的箱变子设备层 key，如 [byr, lvr]；层定义可在界面或 groups.XB 里增删改
rules:                  # 测点 → 值域/单位/变化模型
  - {cat: 电压, min: 3.0, max: 4.2, unit: V, model: walk, match: "v*, *vol", period: 86400}
write:
  interval_ms: 1000
  mode: realtime        # realtime | history
  batch: 100
  points_per_device: 10 # null = 持续写入直到手动停止
  history_start: ''
  rate_limit: 0
  threads: 4
  dry_run: false
  targets: [BMS, PCS, XB]   # 写入对象：只生成并写入这些分组，可只留其中一个
```

### 3. 路径与编码规则（最容易做错，先写测试）

**设备路径** = `root.{station}.{zone}.{signal}` + 逐层编码拼接。

- BMS 是**五层嵌套**：`d / c / cu / p / m`，即 `root.cm.z01.yc.d0001.c101.c001.p01.m01`。
- 堆舱顺序 `order`：`forward` = `d.c`，`reverse` = `c.d`。**这个开关只影响 c 与 d 的拼接顺序**，其余层级顺序不变。
- PCS：`root.cm.z01.yc.pcs0101`；开启 `pcs_sub` 后为 `root.cm.z01.yc.pcs0101.d01`。
- 箱变：`root.cm.z01.yc.35packtran101`；启用子层后为 `root.cm.z01.yc.35packtran101.byr01`（变压器室）、`…lvr01`（低压室）等，每个子层都直接挂在箱变下。
- 信号类型 `yc` → 全部 `FLOAT`；`yx` → 全部 `BOOLEAN`（0/1）。
- 节点数是**相乘**关系：`d × c × cu × p × m`；PCS、箱变是独立分支，各自相加。PCS 子设备数 = `pcs × pcsd`；箱变每个子层各自 = `xb × 该层范围`（兄弟节点，互不相乘），`pcs_sub` 与 `xb_subs` 互相独立。

**编码范围** `range` 支持三种写法，前后端解析结果必须完全一致：

| 写法 | 示例 | 说明 |
|---|---|---|
| 数值连续 | `d0001-d0020` | 前缀相同，按起始宽度补零递增 |
| 尾缀连续 | `c101a-c101d` | 末尾单字母递增 |
| 逐项列举 | `c101,c201` / `c101 c201` | 逗号/中文逗号/空格分隔 |

解析时先规范化连字符两侧空格；展开后**每个编码只需只含字母数字**，不强制带编号：`byr` / `zbhv` 这类单个编码就是一台合法设备；带连字符却没解析成功的写法整体判定为非法（返回 `None`），前端输入框标红 + toast。空字符串视为"未填"，不报错。

**测点定义** `measures`：单点 `soc`，或区间 `v001-v099`（前缀相同且位数一致才展开），`rsv01-rsv07` 同理。展开后的测点数量决定该层每台设备的列数。

### 4. 生成规则引擎

- 规则用**通配匹配**测点名：`v*`、`*vol`、`t*`、`*tem`、`soc`、`rsv01-rsv07`。
- 匹配优先级必须做**特异性排序**，否则 `t*` 会抢走 `totp`、`*de` 会抢走 `workmode`：
  1. 精确名 / 区间展开 → 权重 100
  2. 单字母+`*` 的编号序列（`v*`）→ 只匹配「字母+数字」型名字，权重 40
  3. 前后缀 glob → 权重 `10 + 前缀长 + 后缀长`
- 六种变化模型：
  - `walk`：在上次值上随机游走，步长 = 量程 2%，越界按半幅回弹
  - `sine`：`mid + sin(2πt/period + 随机相位) × 量程/2`
  - `mono`：单调累加，到上限回绕到下限
  - `state`：在 `{min, mid, max}` 三档间随机
  - `const`：恒为下限（预留位常用 0）
  - `flip`：在上下限之间翻转（遥信 0/1）
- 每条序列（`设备路径.测点`）独立维护状态，**惰性创建**——65 万序列不能预分配字典。
- 随机源固定种子（如 42），保证同一配置可复现。
- 类型驱动：`signal=yx` 时全部返回 `BOOLEAN`，模型只决定 0/1 的翻转方式。
- 预留可选 `AnomalyInjector`（按比例乘系数制造尖峰），默认关闭。

### 5. 写入引擎（性能与正确性同等重要）

- **必须用 `insertTablets` 批量提交**，不能逐点/逐设备写。
- **Tablet 的 values 是行优先** `values[行=时间戳][列=测点]`，且 `len(values) == len(timestamps)`。列优先写法在 dry-run 下不报错，接真库必现 `len(timestamps) does not equal to len(values)`。
- 依赖服务端 **auto-schema** 自动建序列，绝不逐条 `CREATE TIMESERIES`（68 万条会跑死）。
- 建库做版本兼容：先 `CREATE DATABASE x`，再回退 `CREATE STORAGE GROUP x`；错误文案含 `already exists / already created / repeatedly` 视为成功；只有语法类错误才换写法，权限/网络错误原样抛出。
- `iter_devices()` 必须是**惰性生成器**，按批消费，内存恒定；某层 `measures` 为空则跳过该层设备（不产出空 Tablet）。
- 两种写入模式：
  - `points_per_device = N`：每设备写 N 个时间点，写完即止。进度条**前 50% 给"构造数据"、后 50% 给"写入"**，两段连续不回退。
  - `points_per_device = 空`：**持续写入**，每个采样周期写一轮（每设备 1 点），时间戳逐轮推进，直到手动停止。
- 停止：`threading.Event` 在**批次之间**检查，当前批写完再中断，不产生半批脏数据。
- 限速：`rate_limit` 点/秒，按"已写点数/目标速率"计算应到时刻，超前才 sleep。
- `dry_run` 用 `MockSession` 跑完整流程（含 Tablet 构造、分批、进度、日志），不连真库——用于无 IoTDB 环境自检。
- 进度分母用 **`writable_devices`（只统计挂了测点的设备）**，不能用全部节点数，否则进度永远到不了 100%。
- 返回结果包含：`series / devices / points / elapsed / stopped / dry_run`，持续模式额外有 `rounds`。

### 6. API 契约

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 返回 index.html |
| GET/POST | `/api/config` | 读/存配置，POST 后立即落盘 `config.yaml`（先写 `.tmp` 再 replace） |
| POST | `/api/test` | 连接测试。支持传 host/port 测指定配置；`quiet=true` 不写日志（指示灯心跳）；超时默认 3s，单次探测超时不要拖到 75s |
| GET | `/api/scale` | 规模统计：`counts/groups/series/devices/writable_devices` |
| POST | `/api/run` | 启动写入线程；已在运行返回 409 |
| POST | `/api/stop` | 置停止标志，下一批后中断 |
| GET | `/api/status` | 运行状态快照 `running/state/result` |
| GET | `/api/logs/stream` | SSE 日志流 |
| GET | `/api/health` | 健康检查 |

SSE 必须**每个连接一条独立队列**（发布/订阅广播）。早期用"一个全局队列 + 各连接 `get_nowait()`"会导致多标签页/重连时日志被互相抢走，表现为**轮次跳号、进度缺段**。队列满时丢旧事件，不阻塞写入线程；一次最多批量下发 200 条。

### 7. 前端页面结构

固定 4 个页签 + 底部常驻控制台：

1. **数据库连接**：左侧连接列表（可新增/删除/切换、逐条显示连通指示灯与延迟），右侧连接表单 + 目标库 + 「测试连接」+ 连接诊断四格（状态/延迟/上次检测/目标库）。
2. **路径与测点**：顶部整行工具条（路径前缀、场站、站区、信号类型 yc/yx、堆舱顺序）→ 通栏「层级与测点」表单 → 底部可折叠「实时路径预览」。
3. **生成规则**：规则表（分类/值域/单位/模型/匹配式/周期）+ 变化模型图例（walk/sine/mono/state/const/flip 六张卡片，每张带一条行为示意曲线、代码章、中文名与一句说明；三列栅格，禁止写成一段连续文字）。
4. **生成与写入**：规模估算四格 + 分层明细（可展开）+ 写入对象多选（BMS / PCS / 箱变，chip 内带各组序列数）+ 写入设置（采样周期/每设备点数/模式/batch/历史起始）+ 生成、停止按钮。

**底部控制台**：可折叠，折叠后只留 42px 标题条；展开显示进度条（百分比、已写/待写设备、已写/待写点数、速率、耗时）+ 分级日志（INFO/WARN/ERROR/SUCCESS 配色）+ 自动滚底。多标签页共享同一份日志流，不允许跳号。

### 8. UI 设计规范（这是"好不好用"的分水岭）

- **固定高度工作台，整页不滚动**：`html,body{height:100%;overflow:hidden}`，`.app{height:calc(100vh - 60px - var(--dockh))}`，控制台展开时内容区自动缩短；滚动只发生在面板/列表内部。
- 视觉：浅色、白底卡片、12px 圆角、`1px` 冷灰描边、极轻阴影；顶栏玻璃拟态（sticky 60px）+ 单行摘要条 + 分段控件式页签。
- **表单类页面禁止左右分栏**。层级配置用**通栏表格式**：列标题（层级 / 编码范围 / 设备数 / 已配测点）只出现一次，每层一行；编码范围输入框是该行最宽的元素（≥400px、高 36px、等宽字体），不要塞进 200px 的窄栏里。
- 信息分层：层级徽标 + 名称 + 测点摘要（超长省略 + `title` 全量）+ 设备数 + 展开箭头；
- 图例类信息（如六种变化模型）用「示意图 + 名称 + 一句说明」的卡片栅格，配内联 SVG 曲线；不要用裸 `<div>` 堆文字，否则会连成一段没有层级的行内流。点整行展开测点编辑，编辑区**先给输入框和快捷按钮，再列已有 chips**（否则 20+ 个 chip 会把输入框顶出视野）。
- 测点录入必须支持**整列粘贴**：输入用单行高度的 `textarea`（`<input>` 会把粘贴的换行压成空格），分隔符认逗号 / 顿号 / 分号 / 空格 / 换行，同名测点去重；「清空」按钮放在「已配测点」行右侧，点一次进入确认态、3 秒内再点才清空。
- 空态明确（"未配置测点"），非法输入即时红边，0 点层用灰色弱化。
- 响应式：`≤820px` 放弃固定工作台回整页滚动、层级行改三行堆叠；`≤860px` 高度收紧内边距；`≤820px` 高度收起页头摘要。
- 键盘可达：可展开行 `role=button` + `tabindex` + `aria-expanded`，支持 Enter/Space。

### 9. 验收清单（必须逐条自测）

- [ ] 改任意层级范围 → 规模估算、路径预览、设备数三处数字同步且一致；前后端解析结果一致。
- [ ] 非法范围（`zzz`、`c1-c`）→ 输入框红边 + 提示，且不写入配置。
- [ ] 空测点层 → 不计入设备数、不产出 Tablet。
- [ ] 整列粘贴 `v008…v021` 一次加入 14 个测点；再粘一次全部判重跳过；「清空」需连点两次才生效。
- [ ] PCS 的「含子设备层」单选、箱变的子层多选各自独立：PCS 开启后多出 `pcs0101.d01` 行；箱变可只勾 `byr`、只勾 `lvr` 或两个都勾，每勾一层多出 `35packtran101.byr01` / `…lvr01` 行，设备数 = 箱变数 × 该层设备数；取消后序列数、设备数、路径预览全部回到未开启时的值。
- [ ] 箱变子层可自定义：`＋ 添加子层` 新建一层（key 如 `hvr`、范围 `hvr01-hvr03`）后，chip 显示 60 台（20 台箱变 × 3），路径预览出现 `…hvr01…hvr03`；改范围立即重算，删层点两次 `×` 才生效，刷新页面后删掉的层不会复活。
- [ ] 写入对象只勾 BMS / 只勾箱变 / 任意组合：日志写明「写入对象：…（已排除 …）」，进度分母与产出设备数一致，被排除的组不产生任何 Tablet。
- [ ] 取消到只剩一个分组时再点，被拦住并提示「至少要保留一个写入对象」。
- [ ] 所选分组没有可写设备时，任务在**连库之前**失败，错误信息点名分组。
- [ ] `dry_run` 全流程可跑通，日志含建库、auto-schema、分批、进度、完成。
- [ ] 真写入抽样核对：随机挑 3 条路径，用 `SHOW TIMESERIES` / `SELECT` 验证序列存在、点数正确、类型符合 `yc/yx`。
- [ ] 点击停止 → 当前批写完后中断，结果为 `stopped=true`，进度不为 100%。
- [ ] 持续写入（点数留空）→ 轮次持续递增、时间戳逐轮推进、可停止。
- [ ] 多开两个标签页 → 日志在两边都完整、不跳号。
- [ ] 1440×900 下四个页签**整页零滚动、无横向溢出**；控制台展开/折叠不遮挡内容。
- [ ] 参考性能：约 5,000 台设备 × 20 万点，真库写入 1~2 秒级；满配 68 万序列不 OOM。

### 10. 已知坑（不要重新踩）

1. `[hidden]` 被 `display:flex` 覆盖 → 空态和详情同时出现。补 `[hidden]{display:none!important}`。
2. 面板 `scrollHeight - clientHeight = 1px` 的亚像素差会闪出滚动条 → 差值 ≤2px 时直接 `overflow-y:hidden`。
3. 媒体查询里的 `.card{padding}` 会盖掉 `.pv-card{padding:0}` → 用 `.card.pv-card` 提高优先级。
4. 单选按钮在 flex 里被压成竖排 → `.radio{white-space:nowrap;flex:0 0 auto}`。
5. 吸顶标签栏半透明会透出下方内容 → 用实底色 + `.stuck` 细阴影。
6. `points_per_device` 传空字符串/0 时，后端要归一为 `None`（持续写入），不能当 0 点。
7. 日志跳号的根因是"共享队列"，不是前端去重逻辑，别在前端打补丁。
8. 测试会通过 `/api/config` 把测点写进 `config.yaml`，**测完必须回滚**，否则污染用户配置。

## 三、迭代提示词模板

后续提需求时，按这个结构描述最容易一次做对：

```
【页面/位置】哪个页签、哪张卡片、哪个状态（默认/展开/空态/窄屏）
【现状问题】具体现象 + 截图（例如"输入框只有 218px 宽、无标签，像数据表不像表单"）
【期望结果】布局关系 + 尺寸下限（例如"通栏单列，输入框 ≥400px、36px 高"）
【不能动】哪些既有行为/样式必须保持（例如"整页仍不能出现滚动条、页签切换动画不许改"）
【验收】怎么判断做完了（尺寸、数字、点击路径）
```

> 经验：这个项目 80% 的返工都来自"左右分栏"和"整页滚动"两个诉求没在提示词里写死。把这两条和"输入框宽度下限"写进约束，能省掉大量来回。
